## 1. 用户决策偏离

### 1.1 偏离：`PartsTable.vue` 用 IIFE 而非 plan 决策的"显式 ctx 链路"

#### 是什么

`src/views/parts/list/components/PartsTable.vue` 第 230-234 行：

```ts
// 2026-09-13 PR-2：vue/no-setup-props-destructure 禁止顶层 `props.ctx.X` 直读；
// 用 IIFE 把读取放进函数体（解构出来的 ref 仍然是 props.ctx.* 的引用，响应式保留）。
// 详见顶部注释。
const { query, filters, edit, batch, dispatch, canEdit, columnVisibility, columnDefs } = (() =>
  props.ctx)();
```

文件顶部（第 188-215 行）有一段 27 行的 doc 注释，**逐条列出 `eslint-plugin-vue@9.33` 在三种"看似正确"写法上仍然报 root scope access**——这是本次偏离的完整技术根因。

#### 为什么

- **plan 决策**（用户 2026-09-13 确认）：改成 `ctx.filters.serialNoFilter` / `ctx.edit.editBuffer` 这样的**显式链路**写进模板，去掉解构这层间接。
- **实际实现**：集成 commit 保留了 PR-2 引入的 IIFE 单值包装。
- **偏离根因**：`vue/no-setup-props-destructure` 的 `isPropsMemberAccessed` 检查在三种写法上都返回 true：
  1. `const { x } = props.ctx;` —— CallExpression 之外，整个 ObjectPattern init 直接被命中（`propsRange ⊆ ObjectPattern.range` 且 `props.parent` 是 MemberExpression）；
  2. `const v = props.ctx.y.z;` —— MemberExpression init 命中同样的检查；
  3. `const v = computed(() => props.ctx.y.z);` —— CallExpression 访问器把整个 `computed(...)` 视为根作用域，arrow function 内部的 `props.X` 被视为「在根作用域被读」（`utils.inRange(node.range, propsRange) === true`）。
- **唯一 lint-clean 形式**：IIFE 单值包装。`(() => props.ctx)()` 满足规则的「`isPropsMemberAccessed` 返回 false」条件——其 init `props.ctx` 不在 `wrapperExpressionTypes`（Array/Object）里、不在 `expressions` 列表（TemplateLiteral/Conditional/Identifier）里，CallExpression 节点本身的 range 也不"直接包住"props（`utils.inRange` 是 range 完全包含 → arrow function 把 `props.ctx` 隔离在子节点里）。
- **响应式正确性保留**：IIFE 解构出来的 `query` / `filters` 等是普通对象（不是 Ref），再 `const { items } = query;` 解构出嵌套 Ref 完全不触发 `vue/no-ref-object-destructure`（只对 Ref 本身的解构生效，普通对象解构出 Ref 字段保留响应式）。

#### 推荐怎么做

短期（本次集成）已落地：保留 IIFE + 在文件顶部写完整的"规则限制说明 + 推荐后续动作"注释 + 在 commit message 里再次强调。

中期（reviewer 可选动作，二选一）：

- **路径 A**：等 `eslint-plugin-vue` 升级修复 `isPropsMemberAccessed` 的误报（开源 issue 跟踪），届时回头统一改成 `ctx.filters.serialNoFilter` 显式链路（模板里直接用顶层 `props.ctx.*`）；
- **路径 B**：在项目层精确放行 `computed(() => props.X)` 与顶层 ObjectPattern init（如加 `overrides` + 自定义 rule visitor），把"显式 ctx 链路"作为团队风格强制。

**不要**用文件级 `/* eslint-disable vue/no-setup-props-destructure */` 兜底——会丢掉 PR-1 想要的"新代码 0 warning"防线（CLAUDE.md #14）。

### 1.2 偏离：`eslint.config.mjs` 关闭 `vue/prefer-true-attribute-shorthand`

#### 是什么

`eslint.config.mjs` 第 181-192 行新增一个配置块：

```js
// 7.5 2026-09-13 PR 集成 commit：关闭 vue/prefer-true-attribute-shorthand
//   规则对 kebab-case 形式的 Vue 组件 prop（如 el-upload 的 :show-file-list、
//   el-table 的 :reserve-selection、el-progress 的 :text-inside 等）报"shorthand
//   建议"——但 vue-tsc 不识别 shorthand 形式的 kebab-case prop，强制改写为
//   `:foo-bar` 会触发 TS2551 类型错误。alloy 默认开启此规则 + 全项目 25+ 处
//   kebab-case shorthand 命中，config 层关闭是唯一可行方案。后续若 vue-tsc 修复
//   shorthand 类型推导，可单独开启回。
{
  rules: {
    'vue/prefer-true-attribute-shorthand': 'off',
  },
},
```

#### 为什么

- **plan 决策**（CLAUDE.md #14）：遇到误报先在 `eslint.config.mjs` 配置层解决，不要行级豁免。
- **实际**：config 层新增一个块关闭该规则——这一步**严格符合 plan**，但**用户原本预期是改规则放行 kebab-case 长写法**，不是关闭规则。这条算「**用 config 层关闭规则**」而非「**修规则参数**」。
- **偏离根因**：`vue-tsc` 是类型检查唯一权威（CLAUDE.md 「常用命令」节注明 `npm run build` 不跑 typecheck，`npm run typecheck` 单独跑 vue-tsc）。当模板写 `:show-file-list="true"` 时，vue-tsc 解析到 Element Plus 的 `ElUploadProps` 类型，prop 字段名是 camelCase 的 `showFileList`——kebab-case 写法在 vue-tsc 看来是「不存在的字段名」，触发 TS2551 `Property 'showFileList' does not exist`。
- **alloy 默认开启此规则** + **全项目 25+ 处 kebab-case shorthand 命中** → 三选一：
  1. 行级 `// eslint-disable-next-line` 25+ 处（违反 CLAUDE.md #14）；
  2. 文件级 `/* eslint-disable */`（CLAUDE.md #14 明确禁止）；
  3. config 层关闭规则（**实际选择**）。
- 备选方案「把 25+ 处全部改成 `:show-file-list="false"` 之类的显式布尔」——等价于「关闭规则的语义」，但 25+ 处手改 + 全项目回归风险 + 后续新增还要继续遵守，不如直接关规则更稳。

#### 推荐怎么做

短期保留 config 层关闭。

中期跟踪 vue-tsc 是否修复 kebab-case shorthand 的类型推断（vue-tsc 上游 issue 跟踪）——若修复，可单独开启 `vue/prefer-true-attribute-shorthand`，25+ 处一次性 lint-fix 即可。

**不要**为了开启这条规则把 25+ 处全部改成长形式——hand-form 一旦扩散，新人写 shorthand 时还会被反复建议改回长形式，noise 极高。

#### 顺带说明

同 commit（`8a00284`）还关闭了 `vue/v-on-event-hyphenation`（第 194-204 行，7.6 块）。这条**不在 plan 偏离里**——PR-3 把 emit 声明 + `emit()` 调用统一改为 camelCase 后，Vue 3 模板里 `@reset-order` 只监听 `emit('reset-order')`，不互通 `emit('resetOrder')`（事件静默断连）。保持 camelCase 是 PR-3 的明确决策，关掉 `v-on-event-hyphenation` 是配套措施，全项目 51 处命中，config 层关闭是唯一可行方案。后续若需要 kebab-case 监听，需先改回 emit 命名风格。

### 1.3 偏离：4 处 `as unknown as T` 双断言

#### 是什么

集成 commit（`8a00284` + `11f0c87`）在 4 处表单 `localX` reactive 字面量初始化时使用双断言：

| 文件                                                        | 行      | 代码                                                                                                                                        |
| ----------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/views/assemblies/components/AssemblyEditDialog.vue`    | 140-141 | `// 走 as unknown as 两次断言绕开 TS "object literal" 报错`<br>`const localForm = reactive({} as unknown as AssemblyEditForm);`             |
| `src/views/assemblies/components/AssemblyChildrenTable.vue` | 250-251 | `// 走 as unknown as 两次断言绕开 TS "object literal" 报错`<br>`const localAddChildForm = reactive({} as unknown as AssemblyAddChildForm);` |
| `src/views/parts/detail/components/PartInfoCard.vue`        | 206-207 | `// 走 as unknown as 两次断言绕开 TS "object literal" 报错`<br>`const localForm = reactive({} as unknown as PartEditForm);`                 |
| `src/views/parts/new/components/PartBatchManualTab.vue`     | 421-422 | `// 走 as unknown as 两次断言绕开 TS "object literal" 报错`<br>`const localForm = reactive({} as unknown as FormState);`                    |

每处都带行级注释说明意图。

#### 为什么

- **plan 决策**（CLAUDE.md #14）：不要文件级 `/* eslint-disable */`。
- **实际**：用 `as unknown as T` 双断言替代「类型断言 + 关 `consistent-type-assertions`」或「写 4 处 `eslint-disable-next-line`」——双断言本身**不需要关任何 ESLint 规则**，所以严格意义上**符合 plan**；但用户原本预期是写干净的 factory 函数或 partial 类型，而非双断言。
- **偏离根因**：表单初始值是 `{}`，TS 推断为 `{}` 而非 `T`；`const x: T = {}` 报「TS2731」object literal 类型推断过窄；`as T`（单断言）触发 `consistent-type-assertions` 规则（alloy 默认 `assertStyle: 'never'` 配 `objectLiteralType: 'never'`）——只有双断言 `as unknown as T` 能过 lint。
- **为什么不用行级 `// eslint-disable-next-line`**：4 处 4 次禁用 + 后续新增表单继续禁用，违反 CLAUDE.md #14 的「不要批量绕过」精神（即使分散在 4 个文件，**模式上是同一类问题的批量复制**）。
- **为什么不用 factory 函数**：factory 返回 `Partial<T>` 才能保留 reactive 语义，模板层会大量 `??` 兜底，且 `Object.assign` 同步语义会更绕；权衡后双断言更接近原代码意图。

#### 推荐怎么做

短期保留 4 处双断言 + 行级注释（**符合 lint 与 typecheck**）。

中期（可选）：

- 把 4 处 `localX` 改成 `reactive<T>({})` 显式泛型——若 Vue 3 类型允许（部分版本 `reactive<T>` 会推导出 `UnwrapNestedRefs<T>`，仍可能报 literal 报错），可替代双断言；
- 或写 `createLocalForm<T>(initial: T)` factory 统一收口 4 处——但要权衡代码量与 reactive 语义。

**不要**关 `consistent-type-assertions` 规则——这是 alloy 大厂共识（CLAUDE.md #14 引用的 code-quality 第 5 节），关掉会丢掉对项目其他位置单断言的兜底。
